# การไหลของข้อมูลในระบบ AI Nurse Scheduling

ระบบใช้ฐานข้อมูล **PostgreSQL** บน Render ข้อมูลไม่ได้เก็บอยู่ในไฟล์ `.db` ภายในเว็บ แต่เก็บในบริการฐานข้อมูลแยกต่างหาก เว็บและโทรศัพท์ติดต่อฐานข้อมูลผ่าน Backend API เท่านั้น

## ภาพรวมการไหลของข้อมูล

```text
ผู้ใช้งานบนเว็บ/โทรศัพท์
        │  HTTPS + JSON
        ▼
React Frontend / Mobile App
        │  /api/v1/...
        ▼
FastAPI Backend
        │  ตรวจ Token และสิทธิ์ผู้ใช้
        │  ตรวจความถูกต้องของข้อมูล
        ▼
SQLAlchemy
        │  อ่าน/เขียนข้อมูล
        ▼
PostgreSQL บน Render
```

1. ผู้ใช้กรอกหรือเลือกข้อมูลในหน้าเว็บ
2. Frontend ส่ง JSON ไปยัง API เช่น `POST /api/v1/leave-requests`
3. Backend ตรวจ Access Token บทบาทผู้ใช้ และกฎของข้อมูล
4. SQLAlchemy แปลงคำสั่งของโปรแกรมเป็น SQL
5. PostgreSQL บันทึกข้อมูลและส่งผลกลับ
6. Backend ส่งผลเป็น JSON ให้หน้าเว็บแสดงผล

## ตารางสำคัญและความสัมพันธ์

| ตาราง | หน้าที่ | เชื่อมโยงกับ |
|---|---|---|
| `users` | บัญชีเข้าสู่ระบบและบทบาท | `staffs.user_id` |
| `departments` | ข้อมูลแผนก | บุคลากร ตารางเวร และกฎ ICU |
| `staffs` | ข้อมูลบุคลากร | บัญชี แผนก เวร วันลา และ Preference |
| `shift_types` | ประเภทเวร เช่น AM, PM, N | รายการจัดเวรและ Coverage Window |
| `schedules` | หัวตารางเวรรายเดือน | แผนกและ `schedule_details` |
| `schedule_details` | เวรของแต่ละคนในแต่ละวัน | ตารางเวร บุคลากร และประเภทเวร |
| `leave_requests` | คำขอลาและสถานะอนุมัติ | บุคลากร |
| `staff_shift_preferences` | เวรที่ต้องการหรือหลีกเลี่ยง | บุคลากรและประเภทเวร |
| `availabilities` | วันที่พร้อมหรือไม่พร้อมขึ้นเวร | บุคลากร |
| `department_rule_settings` | กฎ ICU รายแผนก | แผนก |
| `coverage_windows` | ช่วงเวลาที่ต้องมีคนครอบคลุม | แผนกและประเภทเวร |
| `ai_schedule_drafts` | ผลจัดตารางฉบับทดลองจาก AI | แผนกและรายละเอียด AI Draft |
| `schedule_validation_histories` | ประวัติการตรวจตาราง | ตารางเวร |
| `schedule_audit_logs` | ประวัติการเปลี่ยนสถานะ/เผยแพร่ | ตารางเวรและผู้ดำเนินการ |
| `system_settings` | ค่ากลางของระบบ | Backend ใช้อ่านระหว่างตรวจและจัดเวร |

## ตัวอย่างการไหลของข้อมูลแต่ละหน้า

### หน้าบุคลากร

`แบบฟอร์มบุคลากร → /api/v1/staff → users + staffs → หน้าแสดงรายชื่อ`

- บัญชีเข้าสู่ระบบอยู่ใน `users`
- ข้อมูลชื่อ ตำแหน่ง แผนก และ Senior RN อยู่ใน `staffs`
- การนำบุคลากรออกจะเปลี่ยนสถานะเป็นไม่ใช้งาน ไม่ได้ลบประวัติเวรเดิม

### หน้าวันลา

`แบบฟอร์มวันลา → /api/v1/leave-requests → leave_requests → การตรวจตารางเวร`

คำขอที่อนุมัติแล้วจะถูกนำไปตรวจไม่ให้จัดเวรทับวันลา

### หน้า My Preference

`Preference → /api/v1/staff-preferences → staff_shift_preferences → AI Scheduler`

AI อ่าน Preference เพื่อเพิ่มหรือลดคะแนนของตาราง ส่วน “หลีกเลี่ยง + ความสำคัญ 5” จะถือว่าไม่พร้อมขึ้นเวรทั้งวัน

### หน้า AI จัดตาราง

```text
บุคลากร + วันลา + Preference + กฎ ICU + ประเภทเวร
                         │
                         ▼
                    AI Scheduler
                         │
                         ▼
                 ai_schedule_drafts
                         │ อนุมัติและแปลง
                         ▼
             schedules + schedule_details
```

AI Draft ยังไม่ใช่ตารางจริงจนกว่าหัวหน้าหอจะอนุมัติและแปลงเป็นตาราง Manual จากนั้นต้องตรวจ Validation ก่อนเผยแพร่

## ไฟล์ Export

Admin สามารถไปที่ **ตั้งค่า → การตั้งค่าระบบ → ดาวน์โหลดไฟล์ฐานข้อมูล (.json)** ไฟล์จะประกอบด้วย:

- วันที่และเวลาที่สร้างไฟล์
- ชื่อตารางทั้งหมด
- จำนวนแถวของแต่ละตาราง
- ข้อมูลแต่ละแถวในรูปแบบ JSON
- รายชื่อคอลัมน์ที่ถูกตัดออกเพื่อความปลอดภัย

ระบบไม่ส่งออก `users.password_hash` และไม่ควรอัปโหลดไฟล์ Export ขึ้น GitHub เพราะอาจมีข้อมูลบุคลากร ตารางเวร และเหตุผลการลา
